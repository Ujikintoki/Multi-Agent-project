# Multi-Agent Project for CSIT5520, HKUST

A multi-agent collaboration system using Large Language Models (LLMs) for automated code generation, test generation, and execution feedback, designed for the CSIT5520 NLP course project at HKUST.

Our project is inspired by separating the coding workflow into multiple specialized agents:
- **Programmer Agent**: generates code for HumanEval tasks
- **Test Designer Agent**: generates independent test cases for HumanEval tasks
- **Test Executor Agent**: executes generated code against generated tests and returns feedback

The current implementation focuses on the **HumanEval** benchmark.

## 3. Setup API

Create a `.env` file in the project root directory with your Azure OpenAI credentials.

```bash
AZURE_OPENAI_API_KEY=YOUR_API_KEY
AZURE_OPENAI_ENDPOINT="https://hkust.azure-api.net/"
AZURE_OPENAI_API_VERSION="2025-02-01-preview"
AZURE_OPENAI_CHAT_DEPLOYMENT="gpt-5-mini"
```

Make sure the endpoint, API version, and deployment name match your allocated Azure OpenAI resources.

## 4. Dataset

This project currently uses the **HumanEval** benchmark.

The dataset is loaded directly from Hugging Face:

* Dataset name: `openai_humaneval`
* Split used: `test`

No manual dataset download is required if the environment can access Hugging Face.

## 5. Baseline Generation

The baseline uses a single LLM with zero-shot prompting to generate code completions for HumanEval tasks.

Run:

```bash
cd src
python run_baseline.py
```

Output:

```text
data/baseline_samples.jsonl
```

Each line in the output file has the format:

```json
{"task_id": "HumanEval/0", "completion": "..."}
```

This file is later used for evaluation and can also serve as programmer output for early executor testing.

---

## 6. Baseline Evaluation

To evaluate the baseline with Pass@1, run the evaluation script.

```bash
python eval.py
```

This evaluates the generated baseline code against the HumanEval reference tests.

---

## 7. Test Designer

The **Test Designer Agent** independently generates Python test cases for each HumanEval task.

Its responsibilities are:

* read the HumanEval problem prompt
* generate **Basic Cases**
* generate **Edge Cases**
* generate **Large Scale Cases**
* return only executable Python test code

The design goal is to keep test generation independent from the programmer implementation, so that the generated tests remain more objective.

### Run the Test Designer

To generate the full HumanEval test set:

```bash
cd src
python test_designer_demo.py
```

Output:

```text
data/designer_tests.jsonl
```

Each line in the output file has the format:

```json
{"task_id": "HumanEval/0", "tests": "# Basic Cases\nassert ..."}
```

---

## 8. Test Executor

The **Test Executor Agent** is responsible for:

* reading the HumanEval prompt
* reading programmer-generated code
* reading test-designer-generated tests
* combining them into executable Python
* running the tests
* collecting feedback such as:

  * syntax errors
  * runtime errors
  * assertion failures
  * pass results

The executor takes:

* programmer output (for example `baseline_samples.jsonl`)
* test designer output (`designer_tests.jsonl`)

and uses both as input.

---

## 9. Workflow Summary

The intended workflow is:

1. Load HumanEval task prompt
2. Programmer Agent generates code
3. Test Designer Agent generates test cases
4. Test Executor Agent runs code against tests
5. Executor returns feedback or pass result
6. Programmer may revise code based on feedback

A simplified early-stage workflow is:

1. Generate baseline code with `run_baseline.py`
2. Generate tests with `test_designer_demo.py`
3. Use both files as inputs for executor development

## 10. Main Output Files

### `data/baseline_samples.jsonl`

Baseline code completions generated by the programmer or baseline model.

### `data/designer_tests.jsonl`

Full HumanEval test cases generated by the Test Designer agent.

### `data/agentcoder_results.jsonl`

Reserved for final multi-agent outputs after programmer, test designer, and executor are integrated.

---

## 11. Notes

* The current project focuses on **HumanEval only**.
* The test designer output is an intermediate artifact that is later consumed by the executor.
* The generated `.jsonl` files are useful for reproducibility and should be kept with the project if required by the course submission.
* If model output formatting changes, `src/agents/test_designer.py` contains cleaning logic to sanitize the returned tests.
